# Panel PR 2: Component Kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the shared kit carry the owner's rulings so later page PRs have one button set, one radius rule, one focus rule, two text roles, toned toasts, a described Field and a visible disabled Switch to adopt, plus a `/dev/kit` page that shows every variant and state for capture.

**Architecture:** Bottom-up. `styles/theme.css` states the rules (radius scale, focus ring, the two text roles) as tokens and utilities; `components/ui/*` consume them; the app shell adds the skip link and the theme-color meta; a dev-only route renders the matrix. Page-level adoption is out of scope except where a component change forces the call site to compile again (Button, Task 3).

**Tech Stack:** React 19, TypeScript 5.9, Vite 7, Tailwind 4, vitest 3, react-router 7 (declarative `BrowserRouter` in `src/App.tsx`), `pnpm`.

**Source:** the panel critique items `shell-skip-focus`, `kit-toast-tone`, `kit-switch-disabled`, `kit-field-props`, `kit-mono-overuse`, `kit-button-styles`, `kit-radius-shape`, `kit-numbers-intl`, plus the owner rulings recorded on the critique page.

**Branch:** `panel/component-kit`, cut from `main` after PR 1 (`panel/copy-glossary`) merges.

### Task 6: Toast tones and a Retry action

**Files:**
- Modify: `brawlfarm/web/src/lib/toast.ts` (`ToastOptions` lines 15-18, `ToastItem` lines 20-25, `toast` lines 53-64)
- Modify: `brawlfarm/web/src/components/ui/Toast.tsx` (the container at lines 76-88, the drain bar at 89-97, `onUndo` at 63-74)
- Test: `src/components/ui/Toast.test.tsx`, `src/lib/toast.test.ts`

**Interfaces:**
- `ToastOptions` gains `tone?: "ok" | "bad" | "info"` and `retry?: () => void | Promise<void>`. `ToastItem.tone` is required and the `toast()` factory defaults it to `"info"`, so the component never branches on `undefined`.
- Timings are unchanged: `TOAST_MS` 4000, `TOAST_UNDO_MS` 6000, and the 6 s window applies when `undo` is present. A `retry` does not extend the window. Say so in a comment, because the asymmetry is deliberate and a reviewer will ask.
- Bar colour by tone: `ok` gives `bg-ok`, `bad` gives `bg-bad`, `info` keeps `bg-accent`. The drain mechanics stay exactly as they are: the two `requestAnimationFrame` hops, the reduced-motion branch, the `data-drain` attribute and the width transition.
- Icon by tone from `lucide-react` at `size={14} strokeWidth={1.6} aria-hidden="true"`: `CircleCheck` for ok, `CircleAlert` for bad, no icon for info. The icon is decorative, so tone must not rest on colour and icon alone: a `bad` toast also gets `role="alert"` on the container while `ok` and `info` keep `aria-live="polite"`.
- Actions: a `bad` toast renders `Retry` when the caller passed `retry`; an `ok` toast keeps `Undo` when the caller passed `undo`. Both render as `Button variant="quiet" size="sm"`, the Task 3 name for the old `text` variant. That is the one cross-task dependency, so land Task 3 first, or write `variant="text"` here and fix it during the rebase. Never render two actions in one toast: if a caller passes both, Undo wins and a `console.error` says which was dropped.
- Retry reuses the Undo failure discipline verbatim: dismiss first, then call inside `new Promise((resolve) => resolve(fn()))` so a throw on the way to the request lands in the catch, and route a rejection into one follow-up toast built from `failureMessage(error)` with `tone: "bad"`. A failed retry must not re-arm itself; the follow-up toast carries no `retry`.
- `failureMessage` stays as it is. It must not set a tone; the caller decides that, so the two concerns stay separable.

- [ ] **Step 3: Implement.**
- [ ] **Step 4: Leave every existing caller of `toast(...)` alone.** They all become tone `info`, which is the current appearance, so this task ships no page change. Adopting `ok` and `bad` at the call sites belongs to the pages PR; list it as a deferred sweep.
